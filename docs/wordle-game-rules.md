# Wordle 게임 규칙과 현재 구현

확인 기준일: 2026-09-09

이 문서는 VSCoke의 `/[locale]/game/wordle` 구현을 설명한다. 다른 Wordle 서비스의 규칙이나
향후 기획을 현재 기능으로 간주하지 않는다. 코드와 다르면 아래 구현 근거를 다시 대조해 갱신한다.
검증 목표와 자동화 범위는 [전체 기능 E2E 시나리오의 Wordle 절](./e2e-full-feature-test-scenarios.md#13-wordle)에서 관리한다.

## 1. 플레이 규칙

| 항목             | 현재 동작                                                                             |
| ---------------- | ------------------------------------------------------------------------------------- |
| 목표             | 다섯 글자 영어 단어를 최대 여섯 번의 유효한 제출 안에 맞힌다.                         |
| 보드             | 다섯 칸씩 여섯 줄의 HTML 타일을 표시한다. Phaser·Canvas를 사용하지 않는다.            |
| 단어 선택        | 최초 진입과 재시작마다 서버에서 랜덤 단어를 요청한다. 오늘의 고정 단어 방식이 아니다. |
| 반복 플레이      | 재시작으로 다시 플레이할 수 있다. 일일 플레이 횟수를 누적·제한하는 게임 로직은 없다.  |
| 같은 정답 재출제 | 서버는 이전 정답을 제외하지 않으므로 랜덤 조회 결과가 이전과 같을 수 있다.            |
| 점수             | 점수 계산·표시·누적, 시간 보너스, 연승 보너스가 없다.                                 |
| 누적 기록·랭킹   | 승수·연승·플레이 이력 저장과 Wordle 랭킹 제출 기능이 없다.                            |

정답을 한 번에 맞혀도 여섯 번째에 맞혀도 `won`으로 처리한다. `turn`은 제출 횟수이지 점수가
아니다. [게임 점수 정책](./game-score-policy.md)은 현재 Sky Drop의 서버 랭킹 저장에만 적용된다.

## 2. 입력과 제출

영문 키, `Backspace`, `Enter` 및 화면 키보드 버튼으로 조작한다. 영문 입력은 대소문자를
구분하지 않고 판정 시 대문자로 맞춘다. 물리 키보드의 Ctrl·Alt·Meta 조합은 처리하지 않으며,
버튼·링크·입력 요소에 포커스가 있으면 전역 게임 키 처리보다 해당 요소의 기본 조작을 우선한다.

| 제출 결과                  | 입력과 남은 기회                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------- |
| 다섯 글자 미만             | 길이 안내를 표시한다. 단어 검증 API를 호출하지 않고 입력·시도 횟수를 유지한다.     |
| 사전에 없는 다섯 글자 단어 | 안내 후 현재 입력을 전부 지운다. 시도 횟수는 늘리지 않고 같은 줄에 다시 입력한다.  |
| 유효한 오답                | 글자별 판정 결과를 기록하고 시도 횟수를 한 번 늘린다. 여섯 번째 오답이면 패배한다. |
| 정답                       | 해당 줄의 판정 결과와 시도 횟수를 기록하고 승리한다.                               |
| 단어 검증 API 실패         | 오류 안내를 표시하고 현재 입력·시도 횟수를 유지한다. 재시도할 수 있다.             |

이미 제출한 유효한 오답을 다시 입력하는 것을 금지하는 로직은 없다. 다시 제출하면 기회가
소모된다. 검증 중에는 게임 입력과 중복 제출을 막지만, 이 보호를 재시작 요청까지 보장하는
것으로 해석하지 않는다.

## 3. 글자 판정

| 상태      | 의미                                                  |
| --------- | ----------------------------------------------------- |
| `correct` | 정답과 글자·위치가 모두 같다.                         |
| `present` | 글자는 정답에 있지만 위치가 다르다.                   |
| `absent`  | 정답에 없거나, 중복 문자가 정답의 남은 개수보다 많다. |

먼저 위치까지 같은 글자를 확정한 뒤, 남은 글자 개수 안에서 왼쪽부터 `present`를 부여한다.
예를 들어 정답 `APPLE`에 `ALLEY`를 제출하면 `correct, present, absent, present, absent`다.
정답에 L이 하나이므로 입력한 두 L을 모두 `present`로 표시하지 않는다.

화면 키보드의 누적 판정은 `correct` > `present` > `absent` 순서로 유지한다. 이는 해당 판의
글자 힌트 상태이며, 점수나 다음 판으로 이어지는 기록이 아니다.

## 4. 승패·재시작·저장·공유

정답이면 성공 알림, 여섯 번의 유효한 오답이면 정답을 포함한 실패 알림을 표시한다.
승패가 결정되면 추가 글자 입력과 제출을 막는다. 별도 점수 결과 화면이나 점수 제출은 없다.

재시작은 입력, 제출 기록, 글자 판정, 시도 횟수, 키보드 상태와 승패를 초기화하고 랜덤 단어를
다시 요청한다. 완료 여부와 관계없이 헤더의 재시작 버튼을 사용할 수 있다.

진행 상태는 React 메모리에만 있다. Wordle의 판 상태를 localStorage·sessionStorage·서버에
저장하는 경로가 없으므로, 브라우저 전체 새로고침 또는 컴포넌트 재마운트 시 이전 판을 복원하지
않고 단어를 다시 요청한다. 단순 리렌더링은 재마운트와 다르며, 사이트 공통 방문 탭 기록도
Wordle 판 상태 저장과는 별개다.

헤더 공유 버튼은 Wordle 안내 문구와 현재 페이지 URL을 공유한다. 점수·정답·시도 결과표를
공유하는 기능은 아니다. 공개 점수 결과 링크인 `/share/:id`와 구분한다.

## 5. 클라이언트와 서버의 책임

| 경계                             | 현재 책임                                                                     |
| -------------------------------- | ----------------------------------------------------------------------------- |
| `GET /wordle/word`               | DB에서 랜덤 단어를 골라 정답 문자열 `{ word }`를 반환한다.                    |
| `POST /wordle/check`             | 요청의 다섯 글자·영문 형식과 DB 등록 여부를 검사하고 `{ exists }`를 반환한다. |
| `useWordle`                      | 입력·시도 횟수·키보드 힌트·승패·재시작을 관리한다.                            |
| `EnglishWordleLogic.checkGuess`  | 브라우저에서 정답과 입력의 글자별 위치·개수를 비교한다.                       |
| `EnglishWordleLogic.isValidWord` | 로컬 형식 확인 함수다. 실제 제출 경로의 사전 검증은 서버 API를 사용한다.      |

정답은 API 응답과 클라이언트 상태에 이미 존재한다. 서버가 정답을 숨기거나 승패·점수를
검증하는 경쟁형 구조가 아니다. 단어 로딩에 실패하면 오류를 표시하고 정답이 없는 동안 입력을
처리하지 않는다. 임의의 대체 정답으로 정상 플레이처럼 보이게 하지 않는다.

서버의 단어 조회는 DB의 준비된 단어 집합을 전제로 한다. 조회 쿼리 자체에는 길이·영문 필터와
이전 정답 제외 조건이 없으므로, `/wordle/check`의 입력 검증을 정답 데이터 전체의 검증으로
대체하지 않는다.

## 6. 현재 보장하지 않는 것과 후속 개선

| 구분        | 현재 제한                                                                                    | 후속 검증·개선 목표                                                                       |
| ----------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 재시작 경합 | 재시작 연타 시 요청 중복을 막거나 이전 응답을 취소·무시하는 처리가 없다.                     | 새 판 조회의 단일 진행, 오래된 단어·검증 응답의 새 판 반영 방지를 구현하고 회귀 검증한다. |
| 오류 문구   | 단어 조회·검증 실패에 공통 `Game.apiUnavailable` 문구를 사용한다. 한국어는 서버 이전 안내다. | 실제 이전 작업 여부와 무관한 장애에서도 오해하지 않도록 오류 메시지 정책을 검토한다.      |
| 자동화      | 진입·키보드·일부 오류와 서버 검증 계약을 검사한다.                                           | 승리·패배 완주, 중복 문자 UI, 새로고침, 재시작 경합 검증을 보강한다.                      |
| 미구현 기능 | 점수·랭킹·연승·일일 퍼즐·진행 상태 영속 저장은 없다.                                         | 별도 기획·구현 전까지 현재 제공 기능으로 문서화하지 않는다.                               |

이 문서 최신화는 위 기능을 새로 구현하거나 기존 제한을 해결한 작업이 아니다. 테스트 문서의
`A/P/N/M`은 자동화 범위를 나타내며, 이번 작업에서 모두 실행·통과했다는 의미가 아니다.
