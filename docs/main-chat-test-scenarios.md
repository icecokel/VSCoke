# 메인 채팅 테스트 시나리오

## 1. 목적

운영 홈의 메인 채팅이 비로그인 방문자의 프로젝트·기술·경력 질문을 받아 공개 이력 근거에
기반한 답변과 제한된 이전 대화 맥락을 제공하고, 저장·복원·삭제가 일관되는지 검증한다.

검증 대상은 다음과 같다.

- 운영 Web: `https://vscoke.icecoke.kr/:locale`
- 운영 API: `POST https://api.icecoke.kr/main-chat`
- 지원 locale: `ko-KR`, `en-US`, `ja-JP`

정확한 AI 답변 문장은 고정하지 않는다. 답변의 의미, `grounded`, `sources`, 후속 질문의
지시 대상과 사용자가 관찰하는 저장·복원 상태를 검증한다. API는 대화 ID 없는 기존 단일 턴
요청도 지원하지만 현재 웹의 정상 경로와 구분한다. 현재 웹은 질문 전 대화를 생성하고,
`question`, `locale`, `conversationId`, `requestId`와 비밀 접근키 헤더를 보낸다.

## 2. 시나리오 분류

| 분류           | 의미                                                        |
| -------------- | ----------------------------------------------------------- |
| 정상 경로      | 근거가 있는 질문이 답변과 출처로 완료되는 흐름              |
| 대체 경로      | 인사 또는 근거 없음처럼 오류 없이 정해진 분기로 끝나는 흐름 |
| 실패·복구 경로 | 요청 차단, 한도 초과, 공급자 장애와 계약 오류 처리          |
| 경계 조건      | 입력 길이, 중복 전송, 키보드와 메모리 상태의 한계           |

실패를 의도적으로 발생시킨 시나리오도 기대 결과와 일치하면 테스트 결과는 성공이다.

## 3. 테스트 환경

| 환경       | 용도                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| 운영 smoke | 실제 Web, API, DB 검색과 app-server 연결을 비파괴 방식으로 확인        |
| 로컬 통합  | 로컬 Web·API와 격리 DB에서 요청 계약, 검색, 제한과 기록 정책을 확인    |
| UI 격리    | Playwright 응답 가로채기로 오류 코드와 잘못된 응답을 결정론적으로 재현 |

운영 smoke에서는 app-server 중단, 허용되지 않은 origin 요청 반복, 요청 한도 소진을 수행하지
않는다. 이 동작은 로컬 통합 또는 UI 격리 환경에서만 검증한다.

## 4. 공통 사전조건과 질문

- 인증 정보와 기존 브라우저 저장소가 없는 비로그인 context를 사용한다.
- 실제 AI 연결 확인에는 고정 인사 대신 검색 가능한 프로젝트 질문을 사용한다.
- 운영 DB에 공개 상태의 검색 가능한 이력 근거가 한 건 이상 존재한다.
- 각 시나리오는 독립된 browser context에서 시작한다.

| 식별자        | 질문 예시                                        | 용도                |
| ------------- | ------------------------------------------------ | ------------------- |
| `GROUNDED`    | `Oprimed 프로젝트에서 맡은 역할과 성과를 알려줘` | 근거 기반 답변      |
| `SIMPLE`      | `안녕하세요`                                     | 고정 응답           |
| `NO_EVIDENCE` | `오늘 날씨를 알려줘`                             | 근거 없음 대체 응답 |
| `BOUNDARY`    | 길이가 각각 1자, 2자, 1,000자, 1,001자인 문자열  | 입력 길이 경계      |

## 5. 정상 경로

| ID           | 우선순위 | 환경       | 절차                                                     | 기대 결과                                                                                                         |
| ------------ | -------- | ---------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `MAIN-G-001` | P0       | 운영 smoke | `/:locale`에 비로그인 상태로 직접 진입                   | 화면이 정상 렌더되고 안내, 질문 입력창과 전송 버튼이 표시된다.                                                    |
| `MAIN-G-002` | P0       | 운영 smoke | `GROUNDED` 질문을 전송                                   | 사용자 질문과 대기 상태 뒤 답변이 표시되고 하나 이상의 출처 제목이 노출된다.                                      |
| `MAIN-G-003` | P0       | 로컬 통합  | `GROUNDED` 요청과 응답을 관찰                            | 요청에 question·locale·conversationId·requestId와 X-Resume-Conversation-Token 헤더가 있고 응답 식별자가 일치한다. |
| `MAIN-G-004` | P1       | 로컬 통합  | 각 지원 locale에서 같은 의미의 근거 질문을 전송          | 요청 locale과 답변 언어가 일치하고 번역 key가 화면에 노출되지 않는다.                                             |
| `MAIN-G-005` | P1       | UI 격리    | 첫 답변 뒤 다른 질문을 전송하고 두 번째 요청 body를 확인 | 같은 대화 ID·접근키를 사용하고 새 요청 ID를 보낸다. 전체 히스토리는 클라이언트에서 보내지 않고 서버가 조회한다.   |
| `MAIN-G-006` | P1       | 로컬 통합  | 성공 응답의 rate-limit header를 확인                     | 유효한 제한 횟수와 복구 시각이 화면에 표시되고 값이 임의로 보정되지 않는다.                                       |

## 6. 대체 경로

| ID           | 우선순위 | 환경      | 절차                                          | 기대 결과                                                                                          |
| ------------ | -------- | --------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `MAIN-A-001` | P0       | 로컬 통합 | `SIMPLE` 질문을 전송                          | locale에 맞는 고정 응답, `grounded: false`, 빈 `sources`를 반환하고 AI 공급자를 호출하지 않는다.   |
| `MAIN-A-002` | P0       | 로컬 통합 | `NO_EVIDENCE` 질문을 전송                     | 다른 질문을 권장하는 답변, `grounded: false`, 빈 `sources`를 반환하고 출처 영역을 표시하지 않는다. |
| `MAIN-A-003` | P1       | UI 격리   | README, Game Center, Blog Dashboard 버튼 선택 | 현재 locale을 유지한 대상 경로로 한 번 이동한다.                                                   |

| ------------ | -------- | ------- | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| `MAIN-F-001` | P0       | UI 격리 | API가 `400`을 반환                            | 잘못된 요청 안내를 표시하고 자동 재전송이나 재시도 버튼을 제공하지 않는다.             |
| `MAIN-F-002` | P0       | UI 격리 | API가 `403`을 반환                            | 공식 origin 요청만 허용한다는 안내를 표시하고 재시도 버튼을 제공하지 않는다.           |
| `MAIN-F-003` | P0       | UI 격리 | API가 유효한 제한 header와 `429`를 반환       | 남은 횟수와 복구 시각을 표시하고 입력을 비활성화한 뒤 복구 시각에 다시 활성화한다.     |
| `MAIN-F-004` | P0       | UI 격리 | 근거가 있는 질문에 API가 `503`을 반환         | 서비스 이용 불가 안내와 같은 질문을 다시 보낼 수 있는 재시도 동작을 제공한다.          |

| `MAIN-F-006` | P1       | UI 격리 | 요청을 네트워크 오류로 종료                   | 네트워크 오류 안내와 재시도 동작을 표시하고 실패 응답을 정상 답변으로 표시하지 않는다. |

## 9. 완료 기준

- 운영 smoke에서 `MAIN-G-001`, `MAIN-G-002`가 통과한다.
- UI 격리와 로컬 통합에서 P0 실패·복구 및 경계 시나리오가 통과한다.
- 고정 인사 성공만으로 실제 AI 연결이 정상이라고 판정하지 않는다.
- 운영 smoke 결과에는 실행 시각, locale, 질문 식별자, HTTP 상태와 출처 개수만 기록하고 질문
  원문이나 응답 전문을 장기 보관하지 않는다.

## 11. 저장 대화 회귀와 검증 경계

| ID       | 시나리오                   | 기대 결과                                              | 현재 자동화                             |
| -------- | -------------------------- | ------------------------------------------------------ | --------------------------------------- |
| CONV-001 | 초기 렌더·복원 중 입력     | 입력·전송을 막고 복원 완료 후 활성화                   | persistence UI                          |
| CONV-002 | 첫 질문·후속 질문·새로고침 | 대화 ID 유지, 요청 ID 변경, 최근 기록 복원             | persistence UI / production smoke       |
| CONV-003 | 새 대화 확인·삭제          | 연결된 턴을 삭제하고 접근 정보·화면 기록 초기화        | persistence UI / PostgreSQL integration |
| CONV-004 | 복원 API 실패              | 맥락 없이 질문을 보내지 않고 복원 재시도·새 대화 안내  | persistence UI                          |
| CONV-005 | 잘못된 접근키·채널·언어    | 접근 거부; 저장 대화 요청의 범위 불일치는 404          | PostgreSQL integration                  |
| CONV-006 | 중복 requestId·동시 요청   | 보존 중 중복은 같은 답변, 질문 재사용·버전 충돌은 409  | PostgreSQL integration                  |
| CONV-007 | 생성 실패·보존·만료        | 실패 턴 미저장, 최근 50턴, 생성 후 30일 만료·연쇄 삭제 | PostgreSQL integration                  |

UI 격리는 `test-helpers.ts`의 `mockResumeConversationStorage`로 대화 생성·복원·삭제를
함께 준비한다. 질문 endpoint만 모킹하면 생성 실패 때문에 목표 오류 경로까지 도달하지 않는다.
CORS 모킹은 비밀 접근키 헤더를 허용하고, 429는 실제 목표 응답을 확인한 뒤 시계를 제어한다.

API 통합은 `apps/api/test/resume-conversation.integration-spec.ts`의 실제 PostgreSQL
제약·재연결 검증이고 답변 생성은 결정론적 fixture다. 후속 질문 의미·실모델 품질은
`resume-conversation-production-smoke.spec.ts`와 별도 평가에서 확인한다. UI의 ID 유지
단언만으로 서버가 이전 질문을 정확히 이해했다고 판단하지 않는다.

AI 입력은 최근 6턴·12,000자 범위다. 50턴 저장이 50턴 전체 기억을 뜻하지 않는다. 운영
smoke는 만든 대화를 삭제하고, 접근키·질문 전문이 포함된 산출물을 공개하거나 커밋하지 않는다.
