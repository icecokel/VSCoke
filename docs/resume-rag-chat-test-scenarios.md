# 이력 질문 채팅 테스트 시나리오

## 1. 목적

운영 이력 질문 채팅이 비로그인 방문자의 직무 적합성·프로젝트·기술·업무 방식 질문을 받아
공개 이력 근거와 출처를 명확히 표시하는지 검증한다.

검증 대상은 다음과 같다.

- 운영 Web: `https://vscoke.icecoke.kr/:locale/resume/question`
- README 진입점: `https://vscoke.icecoke.kr/:locale/readme`
- 운영 API: `POST https://api.icecoke.kr/resume-rag/chat`
- 지원 locale: `ko-KR`, `en-US`, `ja-JP`

정확한 AI 답변 문장과 이전 질문을 기억하는 멀티턴 대화는 검증 대상이 아니다. 답변의 의미,
근거 상태, 출처와 사용자가 관찰하는 상태를 검증한다.

## 2. 시나리오 분류

| 분류           | 의미                                                           |
| -------------- | -------------------------------------------------------------- |
| 정상 경로      | 질문 진입부터 근거가 있는 답변과 출처 확인까지의 흐름          |
| 대체 경로      | 근거 없음, 잘못된 저장 데이터처럼 안전한 빈 상태로 끝나는 흐름 |
| 실패·복구 경로 | 요청 차단, 한도 초과, 공급자 장애와 계약 오류 처리             |
| 경계 조건      | 입력 길이, 중복 전송, 저장소, 분석과 반응형 화면의 한계        |

실패를 의도적으로 발생시킨 시나리오도 기대 결과와 일치하면 테스트 결과는 성공이다.

## 3. 테스트 환경

| 환경       | 용도                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| 운영 smoke | 실제 Web, API, DB 검색과 app-server 연결을 비파괴 방식으로 확인        |
| 로컬 통합  | 로컬 Web·API와 격리 DB에서 검색, 질문 기록과 독립 제한을 확인          |
| UI 격리    | Playwright 응답 가로채기로 오류 코드와 잘못된 응답을 결정론적으로 재현 |

운영 smoke에서는 app-server 중단, 허용되지 않은 origin 요청 반복, 요청 한도 소진을 수행하지
않는다. 이 동작은 로컬 통합 또는 UI 격리 환경에서만 검증한다.

## 4. 공통 사전조건과 질문

- 인증 정보와 기존 브라우저 저장소가 없는 비로그인 context를 사용한다.
- 실제 AI 연결 확인에는 검색 가능한 이력 질문을 사용한다.
- 운영 DB에 공개 상태의 검색 가능한 이력 근거가 한 건 이상 존재한다.
- 각 시나리오는 독립된 browser context에서 시작한다.

| 식별자        | 질문 예시                                       | 용도                |
| ------------- | ----------------------------------------------- | ------------------- |
| `GROUNDED`    | `Oprimed에서 어떤 업무를 했어?`                 | 근거 기반 답변      |
| `NO_EVIDENCE` | `날씨도 이력에 포함돼?`                         | 근거 없음 대체 응답 |
| `BOUNDARY`    | 길이가 각각 1자, 2자, 1,000자, 1,001자인 문자열 | 입력 길이 경계      |

## 5. 정상 경로

| ID          | 우선순위 | 환경       | 절차                                                   | 기대 결과                                                                                     |
| ----------- | -------- | ---------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `RAG-G-001` | P0       | 운영 smoke | `/:locale/resume/question`에 비로그인 상태로 직접 진입 | 질문 주제, 입력창과 전송 버튼이 표시되고 로그인을 요구하지 않는다.                            |
| `RAG-G-002` | P0       | UI 격리    | 질문 주제를 펼치고 추천 질문을 선택                    | 추천 질문이 입력창에 채워지고 사용자가 전송하기 전에는 API 요청이 발생하지 않는다.            |
| `RAG-G-003` | P0       | 운영 smoke | `GROUNDED` 질문을 전송                                 | 대기 상태 뒤 답변, 근거 기반 상태, 하나 이상의 출처가 표시된다.                               |
| `RAG-G-004` | P0       | 로컬 통합  | `GROUNDED` 요청과 응답을 관찰                          | Authorization 없이 현재 `question`, `locale`만 전송하고 `grounded: true`, `sources`를 받는다. |
| `RAG-G-005` | P0       | UI 격리    | README에서 질문하고 답변 준비 후 답변 보기를 선택      | `chatId`가 포함된 질문 페이지로 이동하고 준비한 질문, 답변과 출처를 복원한다.                 |
| `RAG-G-006` | P1       | 로컬 통합  | 각 지원 locale에서 같은 의미의 근거 질문을 전송        | 요청 locale과 답변 언어가 일치하고 번역 key가 화면에 노출되지 않는다.                         |
| `RAG-G-007` | P1       | 로컬 통합  | 성공 응답의 rate-limit header를 확인                   | 유효한 남은 횟수와 복구 시각이 표시되며 메인 채팅 제한과 별도 집계된다.                       |

## 6. 대체 경로

| ID          | 우선순위 | 환경      | 절차                                         | 기대 결과                                                                         |
| ----------- | -------- | --------- | -------------------------------------------- | --------------------------------------------------------------------------------- |
| `RAG-A-001` | P0       | 로컬 통합 | `NO_EVIDENCE` 질문을 전송                    | 근거 부족 답변과 상태를 표시하고 출처 목록은 표시하지 않는다.                     |
| `RAG-A-002` | P1       | UI 격리   | 존재하지 않는 `chatId`로 직접 진입           | 예외 없이 추천 질문과 빈 입력창이 있는 초기 화면으로 대체한다.                    |
| `RAG-A-003` | P1       | UI 격리   | 깨진 JSON이 저장된 `chatId`로 직접 진입      | 저장 데이터를 실행하거나 노출하지 않고 초기 화면으로 대체한다.                    |
| `RAG-A-004` | P1       | UI 격리   | 선택적 출처 metadata가 없는 정상 응답을 반환 | 필수 출처 정보만 표시하고 선택 필드 누락 때문에 전체 답변을 실패 처리하지 않는다. |

## 7. 실패·복구 경로

| ID          | 우선순위 | 환경    | 실패 유도                                     | 기대 결과                                                                                               |
| ----------- | -------- | ------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `RAG-F-001` | P0       | UI 격리 | API가 `403`을 반환                            | 공식 origin 안내를 표시하고 무의미한 재시도 버튼을 제공하지 않는다.                                     |
| `RAG-F-002` | P0       | UI 격리 | API가 유효한 제한 header와 `429`를 반환       | 한도 안내와 복구 시각을 표시하고 재시도 시 같은 질문을 한 번 더 보내며 사용자 메시지는 중복하지 않는다. |
| `RAG-F-003` | P0       | UI 격리 | 근거가 있는 질문에 API가 `503`을 반환         | 서비스 이용 불가 안내와 같은 질문을 다시 보낼 수 있는 재시도 동작을 제공한다.                           |
| `RAG-F-004` | P1       | UI 격리 | `answer`, `grounded`, `sources` 계약을 깨뜨림 | 임의 답변으로 대체하지 않고 응답 형식 오류와 재시도 동작을 표시한다.                                    |
| `RAG-F-005` | P1       | UI 격리 | 요청을 네트워크 오류로 종료                   | 네트워크 오류 안내와 재시도 동작을 표시하고 실패 응답을 정상 답변으로 표시하지 않는다.                  |

## 8. 경계 조건

| ID          | 우선순위 | 환경      | 절차                                                     | 기대 결과                                                                                          |
| ----------- | -------- | --------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `RAG-E-001` | P0       | UI 격리   | 공백 또는 1자 질문을 입력                                | 전송 버튼이 비활성화되고 API 요청이 발생하지 않는다.                                               |
| `RAG-E-002` | P1       | 로컬 통합 | 2자, 1,000자, 1,001자 질문을 각각 전송                   | 2자와 1,000자는 허용되고 1,001자는 `400`으로 거절된다.                                             |
| `RAG-E-003` | P0       | UI 격리   | 응답 대기 중 전송 버튼을 빠르게 반복                     | 첫 요청만 전송되고 응답 전까지 입력과 추가 제출이 차단된다.                                        |
| `RAG-E-004` | P1       | UI 격리   | 질문 전송과 성공·실패 analytics event를 확인             | entry point, locale, 분류와 길이만 기록하고 질문 원문은 `dataLayer`에 포함하지 않는다.             |
| `RAG-E-005` | P1       | UI 격리   | 질문 페이지 응답의 CSP header를 확인                     | `connect-src`가 self와 운영 API를 허용하고 불필요한 wildcard를 포함하지 않는다.                    |
| `RAG-E-006` | P1       | 로컬 통합 | 민감 문자열을 포함한 질문의 서버 기록을 확인             | 이메일, 전화번호, token과 secret이 마스킹되고 메인 채팅 질문과 분리되어 기록된다.                  |
| `RAG-E-007` | P1       | UI 격리   | 360x780, 390x844, 430x932에서 긴 대화와 추천 목록을 확인 | 입력창이 화면 하단에 유지되고 대화 영역만 스크롤되며 콘텐츠가 브라우저 viewport를 벗어나지 않는다. |

## 9. 완료 기준

- 운영 smoke에서 `RAG-G-001`, `RAG-G-003`이 통과한다.
- UI 격리와 로컬 통합에서 P0 실패·복구 및 경계 시나리오가 통과한다.
- 근거 부족 응답을 시스템 실패로 오판하지 않는다.
- 운영 smoke 결과에는 실행 시각, locale, 질문 식별자, HTTP 상태, 근거 상태와 출처 개수만
  기록하고 질문 원문이나 응답 전문을 장기 보관하지 않는다.
