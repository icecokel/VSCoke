# 메인 채팅 리디자인 구현 계획

기준 설계:
[메인 채팅 리디자인 설계](../specs/2026-08-08-main-chat-redesign-design.md)

## 목표

홈 `/:locale`을 프로젝트와 이력서 질문을 모두 처리하는 공개 메인 채팅으로 개편한다. 기존
이력서 채팅은 별도 화면으로 유지하고, 메인 채팅은 1시간 30회, 기존 이력서 채팅은 1시간
20회 요청 제한을 독립적으로 관리한다.

## 아키텍처 원칙

- 메인 채팅의 API 계약과 프로젝트 정보 원본을 먼저 확정한 뒤 웹 구현을 시작한다.
- API는 controller, DTO, service, retrieval·answer 책임을 분리한다.
- 메인 채팅은 기존 resume RAG 기능을 재사용하되 기존 이력서 채팅의 요청 횟수 저장소를
  공유하지 않는다.
- API 계약은 `apps/api/openapi.json`과 `apps/web/src/types/api.d.ts`에 동기화한다.
- 웹은 `apps/web/src/features/main-chat`에서 메인 채팅 상태와 API 연결을 관리한다.
- 홈 페이지는 조립 책임만 가지며 채팅 상태와 요청 로직을 직접 쌓지 않는다.
- 운영 런타임에 mock, fixture, sample 응답 fallback을 추가하지 않는다.
- 새 사용자 문구는 `apps/web/messages/{ko-KR,en-US,ja-JP}.json`에서 관리한다.

## Phase 0. 정책과 API 계약 확정

이 페이즈에서는 구현 코드를 작성하지 않고 설계 문서의 미정 항목을 결정한다.

완료일: 2026-08-08

확정 결과:

- 프로젝트와 이력서 모두 공개 `resume_source_items`를 통합 검색한다.
- 별도 질문 유형 분류나 mode 요청 필드를 추가하지 않는다.
- 메인 채팅 endpoint는 `POST /main-chat`으로 한다.
- 요청은 `question`, `locale`을 받고 응답은 `answer`, `grounded`, `sources`를 반환한다.
- 메인 채팅은 기존 공개 origin 정책을 적용하고 독립된 IP별 rolling 1시간 30회 제한을
  사용한다.
- V1 메인 채팅 대화는 브라우저나 서버에 저장하지 않는다.

## Phase 1. 메인 채팅 API

완료일: 2026-08-08

구현 결과:

- `POST /main-chat` 공개 endpoint와 Swagger 계약을 추가했다.
- 프로젝트와 이력서 질문 모두 기존 `ResumeRagService`의 공개 근거 검색을 재사용한다.
- 메인 채팅 전용 `MainChatRateLimitGuard`가 기존 이력서 채팅과 별도 요청 기록을 관리한다.
- 두 guard가 공유하는 sliding-window 계산과 header 설정만 공통 모듈로 분리했다.
- OpenAPI와 웹 생성 타입에 `/main-chat` 계약을 반영했다.

예상 작업 위치:

- 신규: `apps/api/src/main-chat/`
- 수정 가능: `apps/api/src/resume-rag/`
- 수정: `apps/api/src/app.module.ts`
- 수정: `apps/api/openapi.json`
- 수정: `apps/web/src/types/api.d.ts`

### Task 1-1. API 동작 테스트 작성

- [x] 공개 origin의 프로젝트 질문 성공 경로를 검증한다.
- [x] 공개 origin의 이력서 질문 성공 경로를 검증한다.
- [x] 인증 헤더 없이 요청할 수 있음을 검증한다.
- [x] 허용하지 않은 origin, 잘못된 입력, 공급자 실패 응답을 검증한다.

### Task 1-2. 메인 채팅 모듈과 계약 구현

- [x] Phase 0에서 결정한 endpoint와 DTO를 구현한다.
- [x] controller는 전송 계층과 Swagger 계약만 담당하게 한다.
- [x] 질문 처리 orchestration은 service에 둔다.
- [x] 요청 본문과 민감한 원본이 운영 로그 또는 알림에 노출되지 않게 한다.

### Task 1-3. 프로젝트 질문 처리 구현

- [x] 확정된 프로젝트 source of truth를 읽는 retrieval 경계를 구현한다.
- [x] 공개 범위와 locale 조건을 적용한다.
- [x] 검색된 근거만 답변 생성기에 전달한다.
- [x] 근거 부족과 범위 밖 질문을 Phase 0의 응답 원칙대로 처리한다.

### Task 1-4. 이력서 질문 기능 통합

- [x] 기존 `ResumeRagService`의 이력 검색과 근거 기반 답변 기능을 재사용한다.
- [x] 메인 채팅 요청이 기존 이력서 채팅 endpoint를 우회 호출하지 않게 한다.
- [x] 기존 `POST /resume-rag/chat`의 공개 계약과 동작을 변경하지 않는다.

### Task 1-5. 독립 요청 제한 구현

- [x] 메인 채팅 전용 IP별 rolling 1시간 요청 저장소를 구현한다.
- [x] 1~30번째 요청은 허용하고 31번째 요청은 `429`로 차단한다.
- [x] `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`을 반환한다.
- [x] 메인 채팅과 `ResumeRagRateLimitGuard`의 요청 기록이 서로 영향을 주지 않음을 검증한다.

### Task 1-6. OpenAPI와 생성 타입 동기화

- [x] Swagger 설명과 오류 응답을 추가한다.
- [x] `pnpm generate:types`로 OpenAPI와 웹 타입을 갱신한다.
- [x] `pnpm check:api-contract`로 계약 정합성을 확인한다.
