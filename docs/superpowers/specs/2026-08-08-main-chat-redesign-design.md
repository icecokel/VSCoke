# 메인 채팅 리디자인 설계

확인 기준일: 2026-08-08

관련 실행 계획:
[메인 채팅 리디자인 구현 계획](../plans/2026-08-08-main-chat-redesign.md)

## 목표

기존 홈 `/:locale`의 소개 Hero와 Quick Launch 카드 구조를 하나의 공개 채팅 작업면으로
개편한다. 방문자는 로그인하지 않고 프로젝트와 이력서에 관해 자연어로 질문할 수 있고,
대화를 시작하기 전에는 사이트의 주요 항목과 채팅에서 확인할 수 있는 정보를 빠르게 파악할
수 있어야 한다.

## 제품 구조

- 메인 화면은 프로젝트 질문과 이력서 질문을 모두 처리하는 통합 채팅을 제공한다.
- 프로젝트 채팅과 이력서 채팅을 선택하는 모드 전환 UI는 두지 않는다.
- 기존 이력서 채팅 `/:locale/resume/question`은 별도 화면으로 유지한다.
- 메인 채팅에서 이력서 질문을 처리하더라도 메인 채팅 사용 횟수만 차감한다.
- 기존 이력서 채팅의 사용 횟수는 메인 채팅과 공유하지 않는다.

## Phase 0 확정 결정

### 프로젝트와 이력서 정보 원본

메인 채팅의 운영 source of truth는 기존 PostgreSQL `resume_source_items`로 통일한다. 홈,
이력서, 프로젝트 상세의 원본 파일을 채팅 요청 시 직접 읽지 않는다.

검색 대상은 다음 조건을 모두 만족하는 row로 제한한다.

- `status = active`
- `vectorize = true`
- `visibility`가 공개 답변 허용 목록에 포함됨. 기본값은 `public`이다.
- 요청 locale과 같은 locale, 같은 언어군 또는 locale 공통 row

현재 import manifest에 포함된 다음 공개 자료를 프로젝트와 이력서 답변 근거로 사용한다.

- `apps/web/src/constants/resume-data.json`의 현재 이력 데이터
- locale 메시지의 `profile`, `resume` 데이터
- `apps/web/resume-detail`의 공개 프로젝트 상세 MDX
- allowlist에 등록되고 `visibility = public`으로 import된 최종 이력서와 공개 RAG 근거

`private`, `rejected`, `vectorize = false` row와 allowlist에 없는 원본은 공개 메인 채팅에서
검색하지 않는다. 이메일, 전화번호, 비공개 URL 등 직접 연락처가 감지된 원본은 기존 import
규칙에 따라 `rejected` 처리한다.

### 질문 처리 방식

프로젝트 질문과 이력서 질문을 사전에 분류하거나 서로 다른 모드로 라우팅하지 않는다. 두
질문 모두 기존 공개 resume RAG의 keyword 확장, DB text retrieval, 근거 기반 답변 생성
흐름을 사용한다. 키워드는 질문을 차단하지 않고 프로젝트, 경력, 기술, 회사, 제품 개발 관련
검색 토큰을 빠르게 찾는 데 사용한다.

- 모든 고정 응답 외 질문은 같은 공개 corpus에서 근거를 검색한다.
- 검색 결과가 있으면 `grounded = true`와 출처를 반환한다.
- 검색 근거가 없거나 질문이 이력 범위에서 크게 벗어나면 `grounded = false`, 빈 `sources`,
  locale별 다른 질문 권장 답변을 반환한다.
- retrieval 또는 답변 생성 공급자가 실패하면 `503`을 반환한다.

### 메인 채팅 API 계약

- endpoint: `POST /main-chat`
- 인증: 요구하지 않음
- 공개 접근 경계: 기존 `RAG_PUBLIC_CHAT_ORIGINS` allowlist 정책을 동일하게 적용
- 요청 제한: 원본 IP당 rolling 1시간 30회, 기존 이력서 채팅과 별도 저장소 사용

요청 body:

| 필드       | 타입     | 제약                              |
| ---------- | -------- | --------------------------------- |
| `question` | `string` | 2자 이상 1,000자 이하             |
| `locale`   | `string` | `ko-KR`, `en-US`, `ja-JP` 중 하나 |

응답 body:

| 필드       | 타입       | 설명                                    |
| ---------- | ---------- | --------------------------------------- |
| `answer`   | `string`   | 근거 기반 답변 또는 범위·근거 부족 안내 |
| `grounded` | `boolean`  | 검색 근거를 사용했는지 여부             |
| `sources`  | `Source[]` | 답변에 사용한 공개 근거                 |

`Source`는 기존 이력서 채팅과 같은 `title`, `sourcePath`, `sourceKey`, 선택적
`sectionPath`, 선택적 `version`, 선택적 `caveats`, `excerpt`, `similarity`를 제공한다.

성공과 `429` 응답에는 다음 header를 제공한다.

- `X-RateLimit-Limit`
- `X-RateLimit-Remaining`
- `X-RateLimit-Reset`

오류 응답은 기존 전역 오류 envelope인 `success`, `statusCode`, `message`, `timestamp`,
`path`를 사용한다.

| 상태 | 조건                                        |
| ---- | ------------------------------------------- |
| 400  | 질문 길이 또는 locale validation 실패       |
| 403  | 허용된 공식 VSCoke origin이 아닌 요청       |
| 429  | 메인 채팅의 최근 1시간 30회 제한 초과       |
| 503  | 검색 또는 답변 생성 공급자를 사용할 수 없음 |
| 500  | 분류되지 않은 서버 오류                     |

### 대화 저장 범위

V1 메인 채팅 메시지는 현재 페이지의 클라이언트 메모리에서만 관리한다. 새로고침 이후 대화를
복원하지 않으며 서버 저장, `localStorage`, `sessionStorage`를 추가하지 않는다. 새로고침하면
빈 상태로 시작한다. 기존 이력서 채팅의 README 진입용 `sessionStorage` 흐름은 변경하지
않는다.

## 디자인 요구사항

### 시각 방향

메인 화면을 랜딩 페이지가 아니라 대화가 중심인 개발자 작업면으로 구성한다. 기존 다크 톤과
하늘색 액센트는 유지하되, 큰 Hero와 중첩 카드 그리드는 제거한다. 장식보다 메시지, 입력창,
빈 상태 안내의 위계를 우선한다.

- 화면의 중심은 채팅 메시지 영역과 입력창이다.
- 페이지 내부에서 큰 테두리 컨테이너를 반복하지 않는다.
- README, Game Center, Blog Dashboard는 독립 카드가 아니라 간결한 내비게이션 버블로
  표시한다.
- 빈 상태의 소개 문구는 제목 한 줄과 설명 한 줄을 기본으로 한다.
- 액센트 색상은 입력 포커스, 전송 동작, 활성·hover 상태에 일관되게 사용한다.
- 모바일에서도 메시지 영역과 입력창을 우선하고, 빈 상태 안내가 첫 화면을 과도하게
  차지하지 않게 한다.

### 빈 채팅 상태

채팅 메시지가 한 건도 없을 때 다음 순서로 노출한다.

1. VSCOKE를 식별할 수 있는 간결한 제목과 채팅 설명
2. 사이트의 주요 항목을 보여주는 내비게이션 버블
3. `이 채팅에서 확인할 수 있어요` 안내와 4~5개 항목
4. 자연어 질문 입력창과 전송 동작

내비게이션 버블은 다음 기존 화면으로 이동한다.

| 버블           | 이동 경로                 | 역할                    |
| -------------- | ------------------------- | ----------------------- |
| README         | `/:locale/readme`         | 프로필과 경력 요약 확인 |
| Game Center    | `/:locale/game`           | 미니게임 선택 및 플레이 |
| Blog Dashboard | `/:locale/blog/dashboard` | 게시글 목록과 검색      |

채팅에서 확인할 수 있는 정보는 다음 다섯 범주로 안내한다.

- 프로젝트별 목적과 담당 역할
- 프로젝트에서 사용한 기술과 선택 이유
- 문제 해결 과정과 성과
- 경력과 직무 적합성
- 협업 방식과 업무 경험

### 대화 진행 상태

첫 사용자 메시지가 생성되는 즉시 다음 빈 상태 요소를 숨긴다.

- 내비게이션 버블
- `이 채팅에서 확인할 수 있어요` 안내와 전체 항목
- 빈 상태 전용 제목과 설명

대화 중에는 메시지 목록과 입력창을 중심으로 표시한다. 사용자의 질문과 답변은 시각적으로
구분하고, 기존 이력서 채팅이 제공하는 근거와 출처 정보는 이력서 질문 답변에서도 확인할 수
있게 한다.

### 화면 상태

| 상태      | 표시 내용                                                  |
| --------- | ---------------------------------------------------------- |
| 빈 상태   | 소개, 내비게이션 버블, 채팅 안내 4~5개, 입력창             |
| 전송 중   | 사용자 질문, 답변 생성 상태, 비활성화된 중복 전송 동작     |
| 답변 완료 | 사용자 질문, 답변, 제공 가능한 근거와 출처, 입력창         |
| 요청 실패 | 실패 원인 안내, 재시도 가능한 경우 재시도 동작, 입력창     |
| 횟수 초과 | 1시간 30회 제한 안내와 제한 초기화 전까지의 추가 전송 차단 |

### 기본 문구 초안

- 제목: `프로젝트와 경력에 대해 물어보세요`
- 설명: `VSCOKE의 프로젝트, 기술 경험, 이력서 내용을 자연어로 확인할 수 있습니다.`
- 안내 제목: `이 채팅에서 확인할 수 있어요`
- 입력 placeholder: `프로젝트나 경력에 대해 질문해보세요`

실제 사용자 노출 문구는 기존 다국어 메시지 구조에서 관리한다.

## 기능 정의

### F-01. 프로젝트 자연어 질문

- 방문자는 메인 채팅에 프로젝트 설명이나 질문을 자연어로 입력할 수 있다.
- 답변은 VSCOKE가 보유한 프로젝트 정보의 범위에서 처리한다.
- 질문을 위해 프로젝트나 기능 모드를 먼저 선택하게 하지 않는다.

### F-02. 이력서 질문 통합

- 방문자는 메인 채팅에서 경력, 기술 역량, 직무 적합성 등 이력서 관련 질문을 할 수 있다.
- 메인 채팅은 기존 이력서 채팅의 이력 정보 검색과 근거 기반 답변 기능을 포함한다.
- 기존 이력서 채팅 화면은 별도로 유지한다.

### F-03. 사이트 항목 버블

- 빈 상태에서 README, Game Center, Blog Dashboard를 버블 형태로 노출한다.
- 각 버블은 해당 기존 화면으로 이동하는 내비게이션 역할을 한다.
- 버블은 채팅 메시지나 질문 추천으로 취급하지 않는다.

### F-04. 채팅 안내

- 빈 상태에서 채팅으로 확인할 수 있는 정보 4~5개를 간략하게 노출한다.
- 안내 항목은 정보 범위를 설명하며, 자동 질문 전송 기능은 요구하지 않는다.

### F-05. 빈 상태 노출 조건

- 내비게이션 버블과 채팅 안내는 메시지가 없을 때만 노출한다.
- 현재 페이지에서 사용자 메시지가 한 건이라도 생성되면 두 영역을 노출하지 않는다.
- 새로고침하면 메인 채팅 메시지를 복원하지 않고 빈 상태로 시작한다.

### F-06. 공개 접근

- 메인 채팅은 로그인하지 않은 방문자도 사용할 수 있다.
- 질문 전송을 위해 로그인 버튼이나 인증 유도 절차를 노출하지 않는다.

### F-07. 메인 채팅 요청 제한

- 메인 채팅은 원본 IP당 최근 1시간에 최대 30회 요청을 허용한다.
- 31번째 요청부터 제한 시간이 해제될 때까지 추가 요청을 거부한다.
- 프로젝트 질문과 이력서 질문을 구분하지 않고 메인 채팅으로 보낸 모든 요청을 합산한다.

### F-08. 이력서 채팅과 요청 횟수 분리

- 메인 채팅과 기존 이력서 채팅은 서로 다른 요청 횟수 저장소를 사용한다.
- 메인 채팅 한도를 모두 사용해도 기존 이력서 채팅의 남은 횟수에는 영향을 주지 않는다.
- 기존 이력서 채팅 한도를 모두 사용해도 메인 채팅의 남은 횟수에는 영향을 주지 않는다.

## 데이터와 처리 경계

```txt
메인 화면 자연어 질문
-> 메인 채팅 요청 횟수 확인
-> 프로젝트 또는 이력서 질문 처리
-> 답변과 제공 가능한 근거 반환
-> 메인 채팅 메시지 렌더링
```

```txt
기존 이력서 채팅 질문
-> 기존 이력서 채팅 요청 횟수 확인
-> 기존 resume RAG 처리
-> 기존 이력서 채팅 메시지 렌더링
```

두 흐름은 이력서 질문 처리 기능을 공유할 수 있지만 요청 횟수는 공유하지 않는다.

## 범위에서 제외하는 항목

- 로그인 또는 회원별 채팅 사용량 관리
- 프로젝트 채팅과 이력서 채팅을 선택하는 모드 전환 UI
- 기존 이력서 채팅 화면 제거
- 서버 저장형 대화 기록 또는 사용자별 대화 목록
- 메인 채팅의 브라우저 저장형 대화 복원
- 안내 항목을 클릭했을 때 질문을 자동 전송하는 기능
- 새로운 사이트 항목 추가

## 구현 계약 요약

- 프로젝트와 이력서는 공개 `resume_source_items`를 함께 검색한다.
- 메인 채팅은 `POST /main-chat`을 사용한다.
- 메인 채팅은 별도 mode 필드 없이 `question`, `locale`만 받는다.
- `grounded = true`인 답변은 사용한 공개 근거를 `sources`로 제공한다.
- 메인 채팅 대화는 브라우저나 서버에 저장하지 않는다.
- 메인 채팅과 기존 이력서 채팅은 요청 횟수 저장소를 공유하지 않는다.

## 인수 기준

- 비로그인 방문자가 메인 화면에서 채팅 입력창을 보고 질문을 전송할 수 있다.
- 빈 상태에서 README, Game Center, Blog Dashboard 버블이 보인다.
- 빈 상태에서 채팅으로 확인할 수 있는 정보가 4~5개 보인다.
- 첫 메시지가 생성되면 내비게이션 버블과 채팅 안내가 보이지 않는다.
